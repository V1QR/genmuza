# Архитектура

`intent.mjs` задаёт смысловые ориентиры, отделяет явный темп и проверяет JSON музыкального плана. `ai-worker.mjs` загружает встроенный Transformers.js и MiniLM q8; inference выполняется в WASM на CPU, отдельно от аудио и интерфейса. Локальный HTTP-сервер отдаёт подготовленные веса из `models/`; размещённая статическая версия использует фиксированную ревизию Hugging Face и Browser Cache API. Текст пользователя не передаётся облачному inference API.

Модель классифицирует сцену: настроение и энергию. Музыкальные правила переводят эти признаки в темп, лад, гармонию, плотность и аранжировку. MiniLM выполняет feature extraction: mean pooling, нормализация вектора, сравнение косинусного сходства с 18 смысловыми ориентирами. Эти ориентиры — исходные предложения про шесть настроений и три уровня энергии, а не поиск ключевых слов. Схема формируется из классифицированного смысла и явных пожеланий пользователя. План проходит ограничения по известным стилям, ладам, алгоритмам и инструментам; явное указание BPM, ударных, энергии и ряда тембров учитывается дополнительно. JSON не исполняется. Источник подписан «MiniLM · семантический разбор». Пользователь видит план и может изменить его перед `planToProject`. Кнопка отмены завершает Worker и освобождает модель. Быстрый режим использует `quickPlan` и помечен как правила без нейросети.

```text
UI / Game API
     │
     ▼
Project: config + tracks + events + automation
     │                    │
     ▼                    ▼
music.mjs               formats.mjs
PRNG / algorithms       MIDI / JSON / ZIP
Harmony / motifs
Arrangement / thresholds
     │
     ▼
render-worker.mjs ──► dsp.mjs
                        │
            generated oscillators + envelopes
            filters + pan + saturation
            circular delay / reflection tails
            automation + peak headroom
                        │
                 Stereo PCM + stems
                     │       │
                     ▼       ▼
                 player.mjs  WAV export
                 Web Audio

```

`music.mjs` и `dsp.mjs` независимы от DOM. Они работают и в Node для тестов и генерации примеров. `app.mjs` управляет интерфейсом, проектом, историей, импортом, библиотекой и адаптивными состояниями. `server.mjs` только отдаёт статические файлы; он не генерирует музыку и не принимает пользовательские файлы.

## Контракт событий

```js
{
  id: 'lead-0-2-17',
  track: 'lead',
  bar: 0,
  step: 2,
  time: 0.25,       // seconds, humanize/swing included
  note: 71,        // MIDI integer, 0–127
  duration: 0.12,  // seconds
  velocity: 0.6,   // 0–1
  minIntensity: 20 // activate at this threshold
}
```

Набор событий создаётся независимо от текущей интенсивности. Состояния выбирают подмножество событий по `minIntensity`; высоты нот, seed, темп и гармония при переходе не пересоздаются. Сильные доли мелодии привязаны к аккорду, бас — к основному тону / квинте, pad — к трезвучию, bell — к ответным аккордовым тонам.

На каждом новом аккорде выбирается обращение, минимизирующее сумму перемещений трёх голосов с ограничением регистра и ширины. Мелодия выбирает октаву рядом с предыдущей нотой. Это конкретные локальные музыкальные ограничения, а не модель музыкального вкуса.

## Детерминированность

Разные пространства PRNG: `seed:melody:revision` и `seed:drums:revision`. При изолированном обновлении заменяются только соответствующие события. Защищённая дорожка сохраняет вручную изменённые ноты; смена BPM масштабирует её время и длительность. Аудиошум и возбуждение струны также получают seed из дорожки и ID события.

JSON хранит сами события и настройки. Это позволяет восстановить ручные правки, а не только повторить генерацию. `createdAt` — метаданные, не часть музыкального seed. Побитовая идентичность PCM между разными браузерными математическими реализациями не обещается; в одном runtime она проверена.

## Аудио и петля

Каждый голос рендерится в отдельный stem. В режиме loop выход за длину буфера складывается в его начало; эффекты обращаются к циклическому сухому сигналу. Автоматизация интерполируется между тактами, в конце лупа возвращается к первой точке. В полной композиции начало и конец имеют короткий fade, хвост за длиной файла отбрасывается.

Для LPF/HPF используется однополюсный фильтр. Для saw / square — PolyBLEP. FM использует одну несущую и один модулятор с редактируемыми индексом и ratio. Wavetable строится из гармоник без внешних WAV; granular перекрывает синтетические зерна. Physical — шумовая Karplus–Strong петля. Reverb — конечная сеть отражений, не convolution IR.

Микс складывает stems с master и при необходимости ослабляет весь сигнал до 0.94 peak. Stems не нормализуются по одному, чтобы сохранить баланс. MIDI переносит музыку и общие GM-программы; синтез и эффекты остаются в WAV и JSON. На percussion channel 10 громкость дорожек кодируется velocity, чтобы общие channel-controller значения не разрушали баланс ударных.

## Планирование состояний

Worker рендерит новый вариант. После готовности рассчитывается ближайшая будущая граница такта. Новый AudioBufferSource стартует с той же позиции, старый затухает за 65 ms. Следовательно, на медленном устройстве изменение может вступить через несколько тактов; запуск на неверной фазе не используется. Для немедленного hit/safe/victory применяются короткие синтезированные stings.

## Файлы

| Файл | Назначение |
| --- | --- |
| `dist/index.html`, `style.css` | Доступный адаптивный интерфейс, тёмная студия |
| `dist/app.mjs` | Редактор, библиотека, импорт, экспорт, Music Director API |
| `dist/music.mjs` | Теория, seed, композиция, валидация |
| `dist/dsp.mjs` | Чистый аудиорендер |
| `dist/render-worker.mjs` | Worker и передача PCM без копирования |
| `dist/player.mjs` | Web Audio playback и переходы |
| `dist/formats.mjs` | WAV, MIDI, ZIP, JSON |
| `tests/music.test.mjs` | Музыкальные, аудио- и форматные проверки |
| `examples/generate.mjs` | Генерация трёх аудиопримеров |

Расширение требует нового обработчика синтеза в `dsp.mjs`, патчей в `INSTRUMENTS` или нового алгоритма в `sequence`. Структура проекта и интерфейсы этих модулей не привязаны к UI-фреймворку.
